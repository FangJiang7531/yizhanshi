## 1. 三份文档的定位与差异

三份文档并非重复，而是**同一目标在三个抽象层次上的展开**。开发中以其为分工依据，避免"照着一份文档拍脑袋"：

| 文档 | 层次 | 作用 | 在本项目中的使用方式 |
|------|------|------|----------------------|
| **PRD.md** | 需求与验收（最细） | 页面规格、交互细节、数据口径、验收清单（A/B/C 组） | **唯一实现依据**。逐条对照实现（如 §5.2 习惯卡片、§4.4 streak 三口径、附录 B 测试集） |
| **全项目全流程完整策划文档** | 架构与选型（中观） | 技术栈、分层架构、模块化原则、数据隔离与安全策略 | 决定"**怎么搭**"：分层架构、RBAC、主题系统、模块注册表 |
| **全流程分步制作流程文档** | 施工步骤（流程） | 里程碑拆分（M1–M8）、每步的入口/出口条件 | 决定"**按什么顺序做**"、每个节点的验收与提交节奏 |

**关键结论**：三者一致，冲突时以 **PRD 为实现口径**（因为它最具体、可测试），以**完整策划文档为架构口径**，以**分步文档为进度口径**。

## 2. 技术选型（第一阶段定格）

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | **Next.js 15（App Router）+ React 19** | RSC 优先，Server Actions 承担内部前后端交互，天然一体化部署 |
| 语言 | **TypeScript（strict + noUncheckedIndexedAccess）** | 编译期消灭越界访问与隐式 any |
| 样式 | **Tailwind CSS 4 + 语义化 CSS 变量** | 6 主题 × 2 模式 = 12 组变量，切换零闪烁 |
| 数据 | **PostgreSQL 16/17 + Prisma 6** | 强类型 ORM，迁移可回溯；本机以 `@embedded-postgres` 内嵌替代 Docker |
| 校验 | **Zod** | Schema 前后端复用，服务端是安全边界 |
| 认证 | **数据库 Session（非 JWT）** | HttpOnly + Secure + SameSite=Lax Cookie，30 天滑动续期，可服务端即时失效 |
| 密码 | **Argon2id**（memoryCost=19456, timeCost=2, parallelism=1） | 抗 GPU 暴力破解的当前推荐参数 |
| 动效 | **framer-motion + View Transitions API** | 圆形扩散主题切换；`prefers-reduced-motion` 全量降级 |
| 测试 | **Vitest**（单测）+ Playwright（E2E，后续） | 纯函数毫秒级验证 |

## 3. 分层架构与数据流

```
表现层（RSC / Client Components）
      ↓ 调用
控制器层（Server Actions：鉴权 → Zod 校验 → 调服务 → revalidate）
      ↓ 调用
服务层（业务规则；签名不含 HTTP 上下文，userId/timezone 由控制器传入）
      ↓ 调用
仓储层（Prisma 数据访问；所有查询强制带 userId 作用域）
      ↓
PostgreSQL
```

**三条不可逾越的纪律：**

1. **服务层不依赖 HTTP 上下文**——`createXxxService()` 的方法只接收 `{ userId, timezone }` 等显式参数，因此可被单测直接驱动，也能被定时任务/脚本复用。
2. **数据隔离在服务层与仓储层结构化保障**——所有业务查询第一个参数必须是 `userId`；"不存在"与"不属于当前用户"统一返回 `null` → 抛 `NotFoundError`，**不泄漏资源存在性**（防枚举）。
3. **`ActionResult<T>` 统一响应**——只含 `{ success, data | error }`，绝不泄漏堆栈/SQL/内部路径。

### 目录即架构

```
src/
├─ app/                     # 路由层（route groups）
│  ├─ (auth)/login          # 认证页（无平台外壳）
│  ├─ (platform)/           # 登录后外壳：sidebar + topbar + 内容区
│  │  ├─ dashboard  tasks  habits  settings
│  │  └─ blog links bookmarks surveys downloader converter soon   # 占位页
│  ├─ api/health  api/ready # 存活 / 就绪探针
│  └─ layout.tsx            # 注入防闪烁主题脚本
├─ components/              # 跨模块共享 UI（layout / feedback / ui / theme）
├─ config/                  # modules.ts（模块注册表）、env.ts（环境校验）
├─ lib/                     # 与业务无关的基础设施（auth/date/db/errors/logger/…）
├─ modules/                 # 业务模块，每个模块五件套
│  ├─ auth  tasks  habits  analytics
│  └─ _template/            # 新增模块的骨架（假设 H1 的落地）
└─ styles/themes/index.css  # 12 组主题变量 + 组件类 + 动效
```

**每个业务模块固定五件套**（`actions / services / repositories / schemas / components`），跨模块导入由 ESLint 规则禁止——模块边界是**物理的**，不是靠自觉的。

## 5. 数据模型（本期 11 张表 + 7 张预留）

| 模型 | 用途 | 关键约束 |
|------|------|----------|
| `User` / `AuthAccount` | 账号与第三方登录 | 用户名唯一、保留字拦截 |
| `Session` | 数据库会话 | 30 天过期 + 滑动续期 |
| `VerificationCode` | 邮箱验证码 | 时效 + 次数限制 |
| `UserSetting` | 用户偏好（主题/时区） | 一对一 |
| `RateLimitBucket` | 限流桶 | 冷却窗口 |
| `Job` | 异步任务（工具板块预留） | 状态机 |
| `Task` / `Tag` / `TaskTag` | 任务与标签 | `deletedAt` 软删除；多对多 |
| **`Habit`** | 习惯 | `archivedAt`（可恢复）/ `deletedAt`（软删）双语义 |
| **`HabitLog`** | 打卡记录 | **`@@unique([habitId, logDate])`** + **`logDate` 用 `@db.Date`** |
| 预留 | `BlogPost` / `Comment` / `ShortLink` / `LinkVisit` / `Bookmark` / `Survey` / `SurveyResponse` | 仅声明以固化命名规范 |

### 两个决定正确性的设计决策

1. **`HabitLog.logDate` 用 `@db.Date`（只有年月日），冗余存 `userId`**
   打卡语义是"**这一天**有没有打卡"，不是"这一刻打了卡"。若存 timestamp，用户在北京 23:59 打卡、出差到东京查看时会漂移到前一天。`logDate` 由**客户端按用户时区算好日期串**传入，服务端**绝不自行推断"今天"**。
2. **`@@unique([habitId, logDate])` 保障幂等**
   打卡用 `upsert`，重复点击不产生重复记录（B-13）。`userId` 冗余存储让"按用户聚合"少一次 join。

## 6. 安全模型（C 组验收的结构性保障）

| 层 | 手段 | 作用 |
|----|------|------|
| middleware | 粗判 Cookie 有无，注入 `x-pathname` | 未登录快速重定向，避免渲染开销 |
| Server Action | `requireAuth` / `requireNonGuest` / `requireRole` | **能力检查**：访客写操作被拒并弹引导框 |
| 服务层/仓储层 | 强制 `userId` 作用域；不存在与越权同返回 `null` | **结构性数据隔离**：即使控制器被绕过，也读不到别人的数据 |

- **访客模式**：`pending` 只读。所有写操作前置 `requireNonGuest()`，UI 层弹 `GuestPromptDialog` 引导注册。访客数据**不落库**，直接返回预设演示 DTO，从根源消除数据污染。
- **密码与凭据**：Argon2id 哈希，落库前不记日志；`hashIp` 用 `sha256(ip:AUTH_SECRET)` 脱敏。

## 7. 口径固化：streak 三函数（PRD §4.4，禁止自由发挥）

`src/lib/date/streak.ts` 三个**纯函数**，不查库、不取系统时间（参照日作为参数传入）：

| 函数 | 口径 | 易错点 |
|------|------|--------|
| `calcCurrentStreak` | 从"今天"向前回溯；**今天未打卡从昨天数起** | "今天没打卡不算断连"——最重要的产品决策 |
| `calcLongestStreak` | 升序滑动窗口取最长连续区段 | 跨月/跨年/闰年天然连续（按"日期串差 1 天"判定） |
| `calcCompletionRate` | 区间内打卡天数 ÷ 应打卡天数 | **分母只算已过去的天数，不含未来**，否则月初完成率极低 |

**测试即规格**：`tests/unit/streak.test.ts` + `timezone.test.ts` 用固定数据集覆盖 PRD 附录 B 全部 13 条（含 B-11/B-12 时区正确性核心用例），共 39 个用例。

## 8. 主题系统

6 套配色 × 2 明暗模式 = **12 组语义化 CSS 变量**，由 `<html data-theme data-mode>` 驱动。所有组件只引用 `var(--color-*)`，切换主题无需重渲染任何组件。根布局内联 `THEME_NO_FLASH_SCRIPT` 防首屏闪烁；主题切换走 View Transitions API 圆形扩散，并对 `prefers-reduced-motion` 全量降级。

## 11. 已知环境限制
